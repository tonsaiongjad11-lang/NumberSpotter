# Thai Letter Highlight Assistant — ตัวช่วยจับอักษรไทย ก–ฮ

แอป Android Studio / Kotlin สำหรับเกมตาราง **5×5 (25 ช่อง)** โดยเกมแสดง
**พยัญชนะเป้าหมายสีส้ม** และเปลี่ยนตัวอักษรในช่องเมื่อผู้เล่นแตะ

แอปจะจับภาพหน้าจอ *ใหม่ทุกครั้ง* แล้ว:
1. หาตัวอักษรเป้าหมายสีส้มในกรอบม่วง
2. ตัดภาพพยัญชนะจากทุกช่องในตาราง 5×5
3. ทำรูปทรงให้มีสเกลเท่ากัน แล้วเทียบ 25 ช่องกับรูปเป้าหมายล่าสุด
4. วงสีเขียวรอบช่องที่ใกล้เคียงที่สุด **เมื่อมั่นใจเพียงพอ**; ถ้าไม่มั่นใจ **ไม่วง**
5. เมื่อตัวสีส้มหรือข้อมูลในตารางเปลี่ยน จะวิเคราะห์ใหม่ ไม่จำตำแหน่งเดิม

**เป้าหมาย:** พยัญชนะภาษาไทยตั้งแต่ ก ถึง ฮ รวมทั้งพยัญชนะที่ไม่ค่อยใช้ เช่น ฃ ฅ
โดยไม่ได้ผูกกับลำดับตัวอักษรตายตัว และไม่ใช่การกดอัตโนมัติ

**สำคัญ:** รุ่นนี้ใช้ **visual glyph matching** (เทียบภาพตัวอักษร) ไม่ต้องใช้
ML Kit ภาษาอังกฤษหรือโมเดล OCR ไทย — ดังนั้นแอปไม่ได้แปลงพยัญชนะออกเป็นข้อความ
แต่สามารถเทียบอักษรหน้าตาเดียวกันได้ หากฟอนต์ของตัวสีส้มและตารางเหมือนกันหรือใกล้เคียงกัน

## ระบบและสิทธิ์
- Android 10 ขึ้นไป (minSdk 29)
- MediaProjection สำหรับจับภาพหน้าจอตามการอนุญาตของผู้ใช้
- สิทธิ์แสดงทับแอปอื่น เพื่อวาดวงสีเขียว / กรอบตั้งค่า
- Foreground Service แบบ mediaProjection
- **ไม่มี** Accessibility, ไม่มีการแตะจออัตโนมัติ, ไม่มีการส่งภาพไปยังเซิร์ฟเวอร์, ไม่ต้องเชื่อมอินเทอร์เน็ต

## วิธีเปิดและสร้าง APK
1. แตก `ThaiLetterHighlightAssistant.zip` แล้วเปิดโฟลเดอร์ `ThaiLetterHighlightAssistant` ใน Android Studio
2. ให้ Android Studio sync Gradle (ต้องมี Android SDK 35 และ JDK 17)
3. เมนู `Build > Build APK(s)`
4. ได้ไฟล์ที่ `app/build/outputs/apk/debug/app-debug.apk`
5. นำ APK ติดตั้งบนมือถือ Android

หมายเหตุ: ไม่มี Gradle Wrapper ใน ZIP นี้ เพราะสภาพแวดล้อมที่จัดทำไม่ได้
ติดตั้ง Android SDK/Gradle ให้บิลด์ APK ได้; ใช้ Android Studio ที่ติดตั้ง Gradle/SDK พร้อมอยู่แล้วในการ sync และ build

## วิธีใช้
1. เปิดเกมเพื่อดูตำแหน่งจริงของ **ตาราง 25 ช่อง** กับ **พยัญชนะเป้าหมายสีส้ม**
2. เปิดแอปตัวช่วย
3. ใส่กรอบทั้งสองแบบเปอร์เซ็นต์ของความกว้าง/สูงจอ:
   - **ฟ้า:** ตารางทั้ง 25 ช่อง (`L=4, T=28, R=96, B=86` เริ่มต้น)
   - **ม่วง:** บริเวณตัวสีส้ม (`L=68, T=8, R=98, B=23` เริ่มต้น)
4. กด **บันทึกตำแหน่ง** และ **เริ่มอ่านหน้าจอ + วงอักษร**
5. อนุญาตแสดงทับแอปอื่นและการจับภาพหน้าจอเมื่อ Android ถาม
6. กลับไปหน้าเกม ตรวจเส้นกรอบฟ้า/ม่วงให้ตรง แล้วกดช่องที่วงเขียวเอง
7. ถ้าตำแหน่งไม่ตรง กลับมาแอป แก้ตัวเลข แล้ว **หยุดและเริ่มใหม่**
8. หากวงไม่ขึ้น ดูสถานะบนหน้าแอป เพิ่ม/ลดความมั่นใจ (`0.61` เริ่มต้น)
9. หยุดได้ทั้งจากแอปและปุ่ม **หยุด** ในการแจ้งเตือน

## ข้อจำกัดที่ต้องรู้
- ต้องให้พยัญชนะเป้าหมายสีส้มและอักษรในตารางมีรูปร่าง/ฟอนต์ใกล้เคียงกัน
- ตัวอักษรหน้าตาคล้ายกันมาก อาจแยกผิด; แอปมีการเปรียบเทียบคะแนนช่องรอง และยืนยันซ้ำเพื่อเลี่ยงวงผิด
- **ยังไม่ได้ทดสอบกับภาพหน้าจอเกมจริงหรือมือถือจริง** ต้องปรับกรอบตามหน้าจอ
- ไม่มีตัวจับเวลา 0.01 วินาทีการันตี ความเร็วขึ้นกับรุ่นมือถือและ Android
- เกมที่บล็อกการจับภาพ เช่นใช้ FLAG_SECURE จะทำให้ภาพดำและแอปอ่านไม่ได้
- ปรับค่า ROI ให้ครอบเป้าหมายเฉพาะ *ตัวอักษรส้มเดียว* ไม่ติดสีส้มอื่น/ปุ่ม
- ถ้าเกมเปลี่ยนขนาด/หมุนหน้าจอ ต้องเริ่มจับภาพใหม่เพื่อปรับมิติ

## โครงสร้าง
- `MainActivity.kt` — หน้าจอตั้งค่า 2 กรอบ, ความมั่นใจ, ปุ่มเริ่ม/หยุด
- `RegionConfig.kt` — อ่าน/บันทึกค่า ROI
- `CaptureService.kt` — รับภาพหน้าจอ MediaProjection + บริการเบื้องหน้า
- `ShapeMatcher.kt` — แยกรูปพยัญชนะ/เปรียบเทียบรูปร่างทุกช่องทุกเฟรม
- `HighlightOverlay.kt` — วาดวงสีเขียวและเส้นช่วยตั้งค่า
- `CaptureState.kt` — แสดงสถานะการทำงาน

## ความต่างจาก NumberHighlightAssistant เดิม
- เดิมเทียบ *เลขสีส้ม* กับเลข 1–50 ในตาราง 25 ช่อง
- รุ่นนี้เทียบ *พยัญชนะสีส้ม* กับพยัญชนะไทยในตาราง 25 ช่อง
- ยังคงอ่านใหม่ทุกครั้ง **ไม่ใช้ตำแหน่งเดิม ไม่กดแทน** ตามกลไกที่ขอ

## สร้าง APK ผ่าน GitHub Actions (ไม่ต้องติดตั้ง Android Studio)

1. สร้างรีโพซิทอรีใหม่ใน GitHub (แนะนำเป็น **Private**)
2. อัปโหลดไฟล์ทั้งหมดจากโฟลเดอร์โปรเจกต์ รวมโฟลเดอร์ `.github/workflows/`
3. ไปที่แท็บ **Actions** → **Build Android APK** → **Run workflow**
4. รอให้สถานะสำเร็จแล้วเปิดหน้าผลรัน
5. ดาวน์โหลด **ThaiLetterHighlightAssistant-debug-APK** จาก Artifacts และแตกไฟล์ จะพบ `app-debug.apk` สำหรับติดตั้ง

หมายเหตุ: ขั้นตอนนี้ใช้ build server ของ GitHub โดยต้องมีอินเทอร์เน็ต/บัญชี GitHub
และเป็นการสร้าง APK จริงบนเซิร์ฟเวอร์เมื่อ workflow รันสำเร็จ — ไม่ใช่ APK
ที่ได้รับการบิลด์หรือทดสอบแล้วในสภาพแวดล้อมที่เตรียมไฟล์นี้
